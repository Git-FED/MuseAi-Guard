Security architecture / control plane

Separate the decision from the deed.

Muse Guard narrows what an autonomous agent can do by moving authority into independent controls: a human-owned approval queue, a non-AI executor, a constrained proxy, and a record the agent cannot rewrite.

MSP-1 / REFERENCE DESIGNPROPOSE → APPROVE → EXECUTEEXPLICIT LIMITS INCLUDED

One action, ten checks

The agent never gets a direct route to the world.

Every crossing is explicit. The same payload that gets approved is the one the executor revalidates; credentials are attached only behind the proxy.

01

Read, then propose

The agent reads persona and memory, then writes a structured action intent to the queue. A locked kill switch rejects proposals before they enter the workflow.

02

Review out of band

A human reviews the action and its complete payload and approves or denies that item. The decision is recorded in the queue's hash chain.

03

Verify before execution

A separate deterministic process loads an approved item, verifies it has not changed since approval, checks the kill switch again, and runs action validators.

04

Constrain the request

The executor routes an allowed operation through the proxy. The proxy holds the secret, checks the exact-host allowlist, denies everything else, and logs the request.

05

Record and observe

The executor records the result in a hash-chained action log. Independent file, process, and network watchers add visibility alongside the main pipeline.

Trust boundary · agent can influence a proposal, but cannot authorize, execute, or rewrite the controls

Defense in depth

Five controls. Five different jobs.

CONTROL 01STOP

Fail-closed kill switch

Lock state is outside the agent's write path. Missing, corrupt, or unreadable state means the system stays locked.

CONTROL 02AUTHORIZE

Approval queue

Actions wait for an explicit per-item human decision. Hash chaining helps detect edits, deletions, and payload swaps.

CONTROL 03VALIDATE

Deterministic executor

A separate non-AI process rechecks approved intent against action, domain, and protected-path rules before it acts.

CONTROL 04CONSTRAIN

Egress proxy

Credentials live in the proxy's restricted store; exact hosts are allowlisted and all other egress is denied and logged.

Tamper-evident action log

Append-only entries are hash-chained. The agent cannot write to the log; integrity checks make after-the-fact edits detectable.

Independent watchers

File, process, and network monitors compare behavior against known baselines. They add detection; they are not magic prevention.

Threat model

Designed around the unbounded agent.

A system can be tricked by its inputs, misread a goal, or attempt to alter its own environment. The design assumes that possibility and restricts the consequences.

A1Goal-directed overreach

Mitigation: the agent can submit proposals, not carry them out; human approval is required before execution.

A2Prompt injection in content

Mitigation: instructions found in a page or file cannot grant the agent a network path, secret, or approval authority.

A3Credential exposure

Mitigation: the proxy holds credentials, the agent does not; egress rules constrain where requests can go.

A4Log or rule tampering

Mitigation: hash chains and file watchers make changes detectable; the controls are separated from agent-writable paths.

A5Bad or rushed approval

Partial mitigation: per-item review, full-payload visibility, and executor revalidation. Human attention remains a real dependency.

A6Compromised host

Out of scope: root access to the host can read secrets or rewrite code. This design does not claim to defend a fully owned machine.

Honest boundaries

What Muse Guard does not promise.

Not a general AI-safety system

It targets a concrete failure mode: giving an agent access to act without enforceable, independent controls.

Not a defense against a hostile host

A compromised kernel or operator can bypass userspace controls. Protect the host and isolate the workload.

Not a substitute for judgment

A human can approve a harmful action. Full payload review and one-at-a-time approvals reduce—but do not erase—that risk.

The objective isn't a smarter agent. It's a smaller authority surface and a record you can inspect.
