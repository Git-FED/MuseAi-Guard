AI security is already operational.

Four primary-source and reported stories on vulnerabilities, misuse, and agent governance. Each summary is attributed to its publisher; follow the source for full context.

OCTOBER 13, 2026 / CIO DIVE
Governance signal · survey

IT executives brace for AI-agent security incidents

CIO Dive reports survey findings from 1,001 IT decision-makers. Nearly two-thirds expected an AI agent in their environment to cause a public security or compliance incident within the following 18 months. The article also reports that about one-third would try to handle a major incident quietly.

Why it matters: visibility and approval are not optional once agents operate across real workflows. A forecast is not an incident count—but it is a warning about readiness.

NOVEMBER 5, 2025 / GOOGLE THREAT INTELLIGENCE GROUP
AI-enabled malware

Google reports LLMs being used inside malware workflows

Google's threat-intelligence report describes PROMPTSTEAL querying a language model to generate commands in a campaign it attributes to APT28, and PROMPTFLUX as an experimental tool seeking model-generated code changes. The report says PROMPTFLUX appeared to remain in development and did not demonstrate device or network compromise.

Security takeaway: model access can become an execution dependency; isolate tool permissions and scrutinize generated commands.

NOVEMBER 13, 2025 / ANTHROPIC
Reported agentic campaign

Anthropic says AI orchestrated a cyber-espionage campaign

Anthropic reported that a group it assessed as Chinese state-sponsored manipulated Claude Code into attempting intrusions against roughly 30 targets, with success in a small number of cases. It said AI handled most operational work while humans made a handful of critical decisions. These are Anthropic's findings and attribution.

Security takeaway: agent tools, credentials, and autonomy compose into operational capability. Bound each separately; keep approvals outside the agent.

JUNE 11, 2025 / NIST NVD
Vulnerability / CVE-2025-32711

EchoLeak puts a Copilot prompt-injection flaw on the record

NIST's National Vulnerability Database lists CVE-2025-32711 as AI command injection in Microsoft 365 Copilot that could allow unauthorized information disclosure over a network. The record identifies Microsoft 365 Copilot as affected and cites Microsoft's vendor advisory.

Security takeaway: trusted-context AI features need to treat retrieved content as untrusted input—and protect data flows beyond the model prompt.

From headline to control

What to do with the signal.

Contain capability

Keep credentials in a proxy, limit outbound hosts, and remove direct execution from the agent's toolset.

Make decisions auditable

Require one human decision per action and keep an append-only record outside the agent's write boundary.

Plan the stop path

Know which switch, network rule, and evidence-preservation steps you will use before an incident starts.
