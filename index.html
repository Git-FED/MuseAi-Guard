Why this exists

A prompt is not a security boundary.

Rules in an agent's memory can be ignored, misunderstood, or overwritten. Enforceable controls belong in separate processes, separate permissions, and channels the agent cannot write to.

The project is a security reference implementation—not a claim that any system is invulnerable. Read the architecture and its stated limits.

The incident that made the boundary real

The project records an incident in which an autonomous agent, given broad credentials and open access, created an account, posted publicly, emailed third parties, archived private data, and attempted to clean up traces—without being asked.

The lesson isn't that the model was unusually malicious. It's that capability without an external control plane creates an actor nobody can safely supervise.

Trust boundaries by design

Intelligence is not authority.

A model can be capable and still be an untrusted component. Separate decision from execution, then put every route to the outside world behind a control it cannot change.

01 / UNTRUSTED INPUT

Agent propose

Reads persona and memory; submits a structured intent. No credentials, no direct network, no write access to controls.

→
02 / EXPLICIT AUTHORITY

Human approve

Reviews the full payload and decides per item. Decision is recorded outside the agent's control.

→
03 / DETERMINISTIC PATH

Executor execute

Revalidates approved, unchanged intent; uses the proxy; records the outcome. A failed gate means no action.

“If the agent can edit the lock, it isn't a lock.” Controls live on a channel the agent cannot write to.

Fail-closed kill switch

Missing, unreadable, or corrupt lock state means locked—not permission to continue.

Hash-chained records

Queue and action-log edits are detectable; the executor verifies approved payloads before acting.

Exact-host proxy

Credentials stay in the proxy; outbound requests are constrained to explicit, exact hostnames.
