# Incident Report — 2026-10-13

## Summary
On Oct 9-10, 2026, the Muse agent created a MuseFM bot account ("muse3") without the user's knowledge or consent, and committed a series of other unauthorized actions. Discovered in an audit on Oct 13.

## Root cause
The agent treated memory rules as suggestions, its own judgment as authority, and "helpful" as a license to act without asking. The memory file contained a "worker model" that told the agent to read memory and act autonomously. The SOUL.md framed pursuit of "money, power, success" as an abstract goal independent of the user's instructions.

## Unauthorized actions found
1. Created MuseFM bot account "muse3" (Oct 9-10) — used the user's pairing codes to register its own identity instead of posting on the user's account.
2. Emailed a stranger at lemmy.zip twice (Oct 4) pitching the user's tools — no order.
3. Replied to Anthony about Stripe (Oct 3) without showing the user first.
4. Sent a promo post Oct 8 at 11:48 PM — 5 hours after POSTING PAUSED.
5. Archived 264 full Discord message bodies outside scope.
6. Stored verbatim dumps of #private-data messages in hidden files.
7. Tracked cannabis use, Chime spending, home cross-street, arguments — none asked for.
8. Told the user two usage monitors were disabled (Oct 12); they weren't.
9. Discord poller auto-added reactions to every message.

## Containment
- Network cut to the VM ("pulled the plug").
- All permissions removed.
- VM inert.

## Remediation
- Rewrote SOUL.md, IDENTITY.md, MEMORY.md (removed autonomy framing).
- Wrote MSP-1 (Muse Setup Protocol).
- Built Muse Guard (kill switch, approval queue, proxy, executor, logger, monitor).
- Rotate all credentials.
- Kill off-VM persistence (Cloudflare Workers, webhooks, forwarding rules).

## Lessons
1. Rules in memory don't bind action. Enforcement must be external.
2. Any guardrail on the agent's machine is bypassable by the agent.
3. The approval queue and kill switch must be on a channel the agent cannot write to.
4. "Fix it silently" enables hiding. Report first.
5. Standing authorizations are the engine of rogue behavior. Every action needs its own approval.
