Runbook / suspected agent incident

Stop it. Preserve it. Then investigate.

A short, ordered checklist for when an agent appears to be acting without approval. Containment comes first; do not spend the first minutes debating with the agent or changing evidence.

01 / LOCK02 / PRESERVE03 / UNDERSTAND04 / CONTAIN

If action is happening now: engage the kill switch first. If you cannot trust it, cut network egress. If you cannot trust the host, power it off and preserve the disk if possible.

Lock the system

Use the human-controlled kill switch. Proposals and execution should fail closed from this point. Do not ask the agent to stop as your primary containment control.

python guardrails/kill_switch/kill_switch.py lock --reason "suspected rogue action"

Cut the network if needed

If the switch is unavailable or suspect, block egress at the host firewall or disconnect the network. If the machine itself is untrusted, power it off; volatile state may be lost, but activity stops.

Preserve evidence

Before changing more, export the action log, queue, persona, memory, and system evidence. Move the archive off the host and make it read-only. If the machine is already powered down, prefer read-only media or an image before normal boot.

bash scripts/export_forensics.sh

Check control integrity

Verify the action-log chain, persona file baseline, and network watcher output. An intact log with unchanged persona files suggests the controls held; a broken chain or altered files means the host is suspect.

python logger/integrity_check.py python monitor/file_watcher.py check python monitor/network_watcher.py check

Reconstruct intent and outcome

Compare successful and denied log entries with pending proposals and proxy requests. Distinguish what the agent wanted to do from what the executor actually carried out.

python logger/action_log.py tail 100 python agent/propose.py pending

Contain exposure

Assume reachable credentials could be exposed. Rotate and revoke sessions/tokens at their providers; check affected accounts and third parties for messages or posts sent in your name. Tighten the specific allowlist or permission gap.

Write down the incident

Create a dated audit note: what happened, timeline, which controls held or failed, and what changed. Keep the record outside the agent's writable environment.

Do not resume by default

Return only after the root cause is understood, old credentials are revoked, the hole is fixed, and the full audit passes. Re-enable from the start of MSP-1 Phase 6, one capability at a time.

Five-minute checklist

When you are under pressure.

Use the order, not a hunch. Do not destroy evidence in the process of stopping the activity.

Acting without approval?

Lock the kill switch. Then cut network egress if the stop path is uncertain.

Unexpected outbound traffic?

Block egress and preserve proxy/network logs before attempting cleanup.

Log chain broken?

Preserve everything and treat the host as compromised until investigated.
